# Keitaro campaign manager

Обёртка над [Keitaro Admin API](https://admin-api.docs.keitaro.io/) на **FastAPI + SQLAlchemy 2 + Alembic**. Фронт написан на HTML и jQuery (с jQuery UI Autocomplete).

1. **Создание кампании.** На входе название, гео и оффер. Приложение создаёт в Keitaro кампанию с доменом, группой и источником и два потока:
   * **Flow 1:** фильтр «Страна, принимать» по указанному гео, редирект на `https://google.com`;
   * **Flow 2:** без фильтров, выбранный оффер на 100%.
2. **Редактор существующей кампании.** Добавляет и удаляет офферы в потоках, пересчитывает и закрепляет веса, публикует правки в Keitaro (Push) и откатывает их (Cancel). Логика повторяет обёртку из видео, подробности ниже.

В комплекте есть **эмулятор Keitaro** (`fake_keitaro/`). С ним проект запускается и тестируется без настоящего трекера и ключа.

## Быстрый старт

### Демо без ключа: одна команда

```bash
make demo
```

Команда создаёт `.venv`, ставит зависимости, применяет миграции к отдельной `demo.db` и запускает два процесса:
- **эмулятор Keitaro** на :8001 с демо-кампанией из видео (AU → google, 3 оффера);
- **приложение** на :8000.

Интерфейс откроется на http://127.0.0.1:8000, Swagger на http://127.0.0.1:8000/docs. Ctrl+C останавливает оба процесса.

То же самое в Docker:

```bash
docker compose up --build
```

### С настоящим Keitaro

Ключ берётся в админке Keitaro: «Профиль → API ключи → Создать новый ключ». Создайте свой ключ, не используйте чужие из списка.

```bash
make install                # .venv + зависимости, .env из .env.example
# впишите в .env KEITARO_URL (адрес трекера) и KEITARO_API_KEY («Профиль → API ключи»)
make run                    # миграции + uvicorn на :8000
```

В Docker:

```bash
TRACKER_URL=https://tracker.example.com TRACKER_API_KEY=... docker compose up --build
```

Здесь имена `TRACKER_*`, а не `KEITARO_*`. Иначе compose подставил бы значения из локального `.env`, в котором адрес указывает на `127.0.0.1`, а внутри контейнера по этому адресу ничего нет.

Без `make`:

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
alembic upgrade head
uvicorn fake_keitaro.app:app --port 8001 &   # только если работаете с эмулятором
uvicorn app.main:app --reload --port 8000
```

Нужен Python 3.11 или новее, проверено на 3.12 и 3.14.

### Настройки (`.env`)

| Переменная | По умолчанию | Что это |
|---|---|---|
| `KEITARO_URL` | `http://127.0.0.1:8001` (эмулятор) | Адрес трекера, можно без `/admin_api/v1` |
| `KEITARO_API_KEY` | `fake-key` | Ключ из «Профиль → API ключи» |
| `DATABASE_URL` | `sqlite:///./keitaro_manager.db` | Любой URL SQLAlchemy, например Postgres: `postgresql+psycopg://…` (нужно доустановить `psycopg[binary]`) |
| `GEO_REDIRECT_URL` | `https://google.com` | Куда первый поток отправляет посетителей из выбранного гео |
| `OFFERS_CACHE_TTL` | `60` | Сколько секунд кэшируется список офферов для автокомплита |
| `CAMPAIGN_PREFIX` | пусто | Префикс своих кампаний, например `test_ivanov_` (правило тестового трекера). Создатор подставляет его сам. Редактировать через API и интерфейс можно только кампании с этим префиксом, остальные доступны только для просмотра |
| `REPORT_TIMEZONE` | пусто | Часовой пояс отчётов (`Europe/Moscow` и т. п.). Если пусто, используется часовой пояс из настроек трекера |

Удаление офферов прямо в Keitaro можно сымитировать служебной ручкой эмулятора:

```bash
curl -X POST http://127.0.0.1:8001/admin_api/v1/_debug/streams/102/offers \
  -H 'Api-Key: fake-key' -H 'Content-Type: application/json' \
  -d '{"offers":[{"offer_id":3717,"share":100}]}'
```

### Миграции

```bash
alembic upgrade head                                  # применить
alembic revision --autogenerate -m "что поменялось"   # после правок в app/models.py
alembic downgrade -1                                  # откатить последнюю
```

URL базы Alembic берёт из `DATABASE_URL`, см. `alembic/env.py`.

### Тесты

```bash
make test        # или: pytest -q
```

Тесты гоняют весь сценарий из видео через HTTP API приложения. Вместо Keitaro подставлен эмулятор, сеть не нужна.

## Интерфейс

Слева список кампаний из Keitaro с поиском по названию, ID и алиасу. Справа выбранная кампания или форма создания. Адреса страниц — `#/new` и `#/campaign/<id>`, их можно открыть по ссылке. Есть светлая и тёмная тема (по настройке системы), интерфейс работает и на телефоне.

### Новая кампания

- **Название**, **гео** и **оффер**.
  - Гео выбирается из списка с поиском по названию на русском и по коду ISO. Можно вставить готовый список `MX, AU, RO`, Backspace убирает последнюю страну.
  - Оффер ищется по ID или названию.
- **Домен**, **группа** и **источник** выбираются из списков Keitaro. Группу и источник можно создать прямо из формы.
- Ошибки показываются у полей, а не всплывающими сообщениями.
- Справа в реальном времени видно, что будет создано: ссылка, поток 1 со странами и редиректом, поток 2 с оффером на 100%.
- После создания сразу открывается страница кампании.

### Страница кампании

- **Шапка.** Ссылка кампании с кнопкой копирования, ссылка в админку Keitaro (только для настоящего трекера), время последней синхронизации и кнопка «Загрузить из Keitaro» (Fetch streams).
- **Статистика.** Строится через `POST /report/build`.
  - Периоды: сегодня, вчера, 7 дней, 30 дней, этот месяц, всё время.
  - Плитки: клики, уникальные, боты (доля от кликов), конверсии, CR, доход и EPC.
  - График кликов по дням с подсказкой по наведению: клики, уникальные, боты, конверсии, доход за день.
  - Если отчёты недоступны (например, у тарифа нет Admin API для отчётов), показывается ошибка, а редактор работает дальше.
- **Потоки.** Цифры по каждому потоку и таблица офферов: доля, клики, уникальные, боты, конверсии, CR, доход, строка «Итого». Полоса над таблицей показывает распределение долей.

### Чужие кампании

В тестовом трекере есть кампании других участников. Если задан `CAMPAIGN_PREFIX`:
- слева по умолчанию показываются только свои кампании, переключатель «Мои / Все» показывает и остальные;
- чужая кампания открывается только для просмотра и статистики: кнопок редактирования нет, а API на любую правку отвечает 403.

### Удобство и защита от ошибок

- Пока запрос не вернулся, действия заблокированы: двойной клик не добавит оффер дважды.
- Неопубликованные изменения отмечены жёлтой рамкой потока, счётчиком на кнопке «Опубликовать» и панелью внизу экрана. Панель закреплена внизу, чтобы её появление не сдвигало кнопки под курсором.
- Перед публикацией окно подтверждения показывает, какие офферы и с какими долями останутся в Keitaro и какие будут убраны.
- Подтверждение спрашивается, если с черновиком уйти со страницы, загрузить данные из Keitaro (черновик будет заменён) или закрыть вкладку.
- «Опубликовать» неактивна, пока сумма долей не равна 100%, и под таблицей объясняется почему.

## Как работает редактор

1. Откройте кампанию в списке слева и нажмите **«Загрузить из Keitaro»**.
2. Потоки с офферами разбираются и показываются с долями. Потоки без офферов (например, гео-редирект на google) сохраняются только как поток, их содержимое не разбирается.

Кнопки названы по-русски. В скобках указано название из видео.

| Кнопка | Что происходит |
|---|---|
| **Добавить** (Add) | Поиск оффера по ID или названию (автокомплит → `/api/offers/search` → `GET /offers` в Keitaro). Оффер получает метку «Будет добавлен», доли пересчитываются, поток становится **жёлтым** (не опубликован). В Keitaro пока ничего не меняется |
| **Убрать** (Remove) | Оффер становится серым с меткой «Будет убран», его доля 0%, остальные доли пересчитываются, поток жёлтый |
| **Опубликовать** (Push) | `PUT /streams/{id}` с активными офферами и их долями. Затем поток перечитывается из Keitaro, и база приводится к тому, что реально сохранилось в трекере. Если Keitaro сохранил не то, что отправили, появится предупреждение |
| **Отменить** (Cancel) | Откат неопубликованных правок. Офферы, добавленные после последней публикации, отвязываются от потока (сам оффер в справочнике `offers` остаётся). Убранные возвращаются, доли становятся как в Keitaro, поток снова белый |
| **Вернуть** (Bring back) | Возвращает оффер из архива, поток жёлтый |
| **Замок** (закрепить вес) | Зафиксированная доля не меняется при добавлениях и удалениях. Остаток `100 − Σзафиксированных` делится поровну между остальными офферами. Зафиксированное число можно поменять прямо в поле. Если долю поменяли прямо в Keitaro, фиксация при загрузке снимается |
| **Загрузить из Keitaro** (Fetch streams) | Офферы, о которых приложение знало, но которых больше нет в Keitaro, **не удаляются**, а уходят в архив («В архиве», серые) с кнопкой «Вернуть». Черновик приводится к состоянию Keitaro |

**Веса** всегда целые и в сумме дают 100: 3 оффера → 34/33/33, 4 → 25/25/25/25, закреплённый 25% + 2 оффера → 25/38/37. Push запрещён, если в потоке нет активных офферов или сумма не равна 100 (такое бывает, если закрепить все веса). Закрепить веса больше чем на 100% нельзя.

### Модель данных

```
campaigns      id = ID в Keitaro, name, alias, domain, group, source
streams        id = ID в Keitaro, campaign_id, name, position, schema, has_offers
offers         id = ID в Keitaro, name — локальный справочник офферов
stream_offers  привязка «оффер в потоке»:
                 active / share            — черновик (что видно в редакторе)
                 published_active / _share — что сейчас лежит в Keitaro
                 pinned                    — вес закреплён
                 is_new                    — ещё не публиковался (Cancel удалит привязку)
```

Поток «жёлтый», если черновик хотя бы одной привязки отличается от опубликованного состояния. Статус оффера в UI определяется так:

| | опубликован | не опубликован |
|---|---|---|
| **активен в черновике** | `active` | `added` |
| **не активен** | `removing` | `removed` (архив) |

### Что уходит в Keitaro при создании кампании

```jsonc
POST /campaigns   {"name", "alias": <6 случайных символов>, "type": "position",
                   "domain_id", "group_id", "traffic_source_id", "cost_type": "CPC", ...}
POST /streams     {"campaign_id", "type": "regular", "name": "Geo MX,AU → Google", "position": 1,
                   "schema": "redirect", "action_type": "http", "action_payload": "https://google.com",
                   "filters": [{"name": "country", "mode": "accept", "payload": ["MX","AU"]}]}
POST /streams     {"campaign_id", "type": "regular", "name": "Offers", "position": 2,
                   "schema": "landings", "action_type": "http",
                   "offers": [{"offer_id": 3749, "share": 100, "state": "active"}]}
```

Если создание потока упало, кампания отправляется в архив (`DELETE /campaigns/{id}`), чтобы в трекере не остался «огрызок».

## API

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/meta` | эмулятор или настоящий трекер, ссылка на админку (ключ не отдаётся) |
| GET | `/api/refs` | домены, группы кампаний, источники |
| POST | `/api/refs/groups`, `/api/refs/sources` | создать группу или источник `{name}` |
| GET | `/api/offers/search?q=` | автокомплит офферов |
| POST | `/api/campaigns` | создать кампанию `{name, geo, offer_id, domain_id, group_id, traffic_source_id}` |
| GET | `/api/keitaro/campaigns` | кампании из трекера |
| GET | `/api/campaigns/{id}` | кампания из локальной базы |
| GET | `/api/campaigns/{id}/stats?period=7d` | статистика: итоги, по потокам, по офферам, по дням (`today`, `yesterday`, `7d`, `30d`, `month`, `all`) |
| POST | `/api/campaigns/{id}/fetch` | Fetch streams |
| POST | `/api/streams/{id}/offers` | Add `{offer_id}` |
| POST | `/api/streams/{id}/cancel` | Cancel |
| POST | `/api/streams/{id}/push` | Push |
| POST | `/api/stream-offers/{id}/remove` | Remove |
| POST | `/api/stream-offers/{id}/restore` | Bring back |
| POST | `/api/stream-offers/{id}/pin` | закрепить `{share?}` |
| POST | `/api/stream-offers/{id}/unpin` | открепить |

## Допущения о Keitaro API

В OpenAPI-спецификации Keitaro не описаны три вещи. Сделано по тому, как ведёт себя трекер:
* фильтр по стране называется `country`, режим `accept`, в `payload` передаётся список ISO-кодов;
* `action_type: "http"` означает обычный HTTP-редирект;
* `PUT /streams/{id}` с массивом `offers` **заменяет** список офферов потока целиком.

Отчёты: `POST /report/build` с `range.interval`, `dimensions` (`stream_id`, `offer_id`, `day`), метриками `clicks`, `campaign_unique_clicks`, `bots`, `conversions`, `revenue` и фильтром `campaign_id EQUALS`. В спецификации ключ метрик встречается и как `measures`, и как `metrics`. Клиент отправляет `measures`, а если трекер ответит 400, повторяет запрос с `metrics`.

Эмулятор генерирует стабильную синтетическую статистику, только начиная с даты создания потока. На настоящем трекере цифры берутся из самого Keitaro.

После Push обёртка перечитывает поток и сверяет результат с отправленным. Если Keitaro сохранил что-то другое, в интерфейсе появится предупреждение.
